# Kubernetes Overview

쿠버네티스의 기본 개념을 정리한다.

## 노드 (Node)

- 쿠버네티스가 설치된 물리적 또는 가상 머신.
- 워커 머신으로, 쿠버네티스에서 컨테이너가 시작되는 곳.
- 과거에는 **미니언(Minion)** 으로도 불렸다.

실행 중인 노드에 장애가 발생하면 어떻게 될까? 애플리케이션이 중단되지 않으려면 노드가 **두 개 이상** 있어야 한다.

## 클러스터 (Cluster)

- 함께 그룹화된 노드의 집합.
- 한 노드에 장애가 발생해도 다른 노드를 통해 애플리케이션에 계속 접근할 수 있다.
- 여러 노드가 부하를 나눠 처리할 수 있다.

## 마스터 (Master)

클러스터가 구성되면 다음과 같은 의문이 생긴다.

- 클러스터 관리는 누가 담당하는가?
- 구성원 정보는 어디에 저장하고, 어떻게 모니터링하는가?
- 노드에 장애가 발생하면 해당 노드의 워크로드를 다른 워커 노드로 어떻게 옮기는가?

이 역할을 **마스터**가 맡는다.

- 쿠버네티스가 설치되어 마스터 역할로 구성된 별도의 노드.
- 클러스터의 노드를 감시한다.
- 워커 노드에서 컨테이너의 실제 오케스트레이션을 담당한다.

## 구성요소 (Components)

쿠버네티스를 설치하면 다음 구성요소가 함께 설치된다.

| 구성요소 | 역할 |
|----------|------|
| API 서버 | 쿠버네티스의 프런트엔드. 사용자, 관리 장치, 명령줄 인터페이스(CLI)가 모두 API 서버를 통해 클러스터와 상호작용한다. |
| etcd | 클러스터 관리에 쓰이는 모든 데이터를 저장하는 분산형 키-값 저장소. |
| 스케줄러 | 새로 생성된 컨테이너를 찾아 적절한 노드에 배포·할당한다. |
| 컨트롤러 | 클러스터의 "두뇌". 노드, 컨테이너, 엔드포인트가 다운되면 이를 감지·대응하고 새 컨테이너를 띄울지 결정한다. |
| 컨테이너 런타임 | 컨테이너를 실행하는 기반 소프트웨어. 주로 Docker를 쓰지만 다른 런타임도 사용할 수 있다. |
| Kubelet | 각 노드에서 실행되는 에이전트. 컨테이너가 노드에서 예상대로 실행되는지 확인한다. |

### etcd

- 클러스터에 노드와 마스터가 여러 개인 경우, 모든 정보를 클러스터 전반에 분산하여 저장한다.
- 마스터 간 충돌이 생기지 않도록 클러스터 내에서 잠금(lock)을 구현한다.

## 마스터 노드 vs 워커 노드

| 구분 | 마스터 노드 | 워커 노드 |
|------|-------------|-----------|
| 역할 | 클러스터 관리·제어 | 컨테이너 호스팅 |
| 주요 구성요소 | kube-apiserver, etcd, 컨트롤러 매니저, 스케줄러 | Kubelet, 컨테이너 런타임 |

- **워커 노드**: 컨테이너가 호스팅되는 곳. Docker 컨테이너를 실행하려면 컨테이너 런타임이 설치되어 있어야 한다.
  - **Kubelet**은 마스터와 상호작용하며 워커 노드의 상태를 전달하고, 마스터가 요청한 작업을 수행한다.
- **마스터 노드**: kube-apiserver가 있어 마스터 서버 역할을 한다.
  - 수집된 모든 정보는 etcd 기반의 키-값 저장소에 저장된다.
  - 컨트롤러 매니저와 스케줄러도 마스터에 있다.

## kubectl

쿠버네티스 CLI 도구. 클러스터의 상태를 확인하고, 클러스터에 애플리케이션을 배포·관리할 때 사용한다.

```bash
kubectl run hello-world   # 애플리케이션 실행
kubectl cluster-info      # 클러스터 정보 확인
kubectl get nodes         # 클러스터의 노드 목록 확인
```
