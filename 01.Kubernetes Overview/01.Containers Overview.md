# Containers Overview

## Docker의 목적

다양한 애플리케이션을 패키징하고 컨테이너화하여 **언제 어디서나 원하는 만큼 실행**할 수 있도록 하는 것.

## 컨테이너 vs 가상 머신

두 방식의 차이는 **가상화가 이루어지는 계층**에서 발생한다.

| 구분 | Docker (컨테이너) | 가상 머신 (VM) |
|------|------------------|----------------|
| 구조 | 하드웨어 → OS → Docker → 컨테이너 | 하드웨어 → 하이퍼바이저(예: ESXi) → VM |
| OS / 커널 | 호스트 OS와 커널을 공유 | VM마다 자체 OS와 커널을 보유 |
| 라이브러리 / 종속성 | 컨테이너별로 포함 | VM 내부 OS 위에 별도로 포함 |
| 리소스 사용률 | 낮음 | 높음 (OS와 커널이 여러 개) |
| 크기 | 가벼움 | 무거움 |
| 부팅 속도 | 빠름 | 느림 |
| 격리성 | 상대적으로 낮음 | 완전히 격리됨 |

### Docker

- 기본 하드웨어 인프라 위에 OS가 있고, 그 OS에 Docker가 설치된다.
- Docker가 라이브러리와 종속성을 포함한 컨테이너를 단독으로 관리한다.
- 호스트의 커널을 컨테이너끼리 공유하므로 가볍고 부팅이 빠르다.
- 반면 커널 등 더 많은 리소스를 공유하기 때문에 격리성은 VM보다 떨어진다.

### 가상 머신

- 하드웨어 위에 ESXi 같은 하이퍼바이저가 있고, 그 위에서 VM이 실행된다.
- 각 VM 내부에 자체 OS가 있고, 그 위에 종속성과 라이브러리가 존재한다.
- 게스트 OS와 커널이 VM 수만큼 존재하므로 기본 리소스 사용률이 높다.
- 호스트 OS나 커널에 의존하지 않아 기본적으로 완전히 격리된다.
