# YAML Introduction

쿠버네티스의 오브젝트(Pod 등)는 대부분 YAML 파일로 정의한다. XML이나 JSON 같은 데이터 구조 형식을 써본 적이 있으면 이해하기 쉽다.

## 기본: 키와 값

데이터를 **키: 값** 형태로 표기하며, 콜론(`:`)으로 키와 값을 구분한다.

```yaml
Fruit: Apple
Vegetable: Carrot
```

## 배열 (List)

항목 앞에 대시(`-`)를 붙여 표현한다.

```yaml
Fruits:
- orange
- apple
- banana
```

## 딕셔너리 (Dictionary)

같은 들여쓰기로 속성을 나열하면, 하나의 키 아래에 **그룹화된 속성 집합**이 된다.

```yaml
Banana:
    Calories: 105
    Fat: 0.4g
```

## 들여쓰기가 중요하다

각 항목 앞의 **공백 수**로 계층을 구분한다. 같은 내용이라도 공백이 달라지면 다른 구조가 된다.

```yaml
# 올바른 예: Calories와 Fat이 Banana의 속성
Banana:
    Calories: 105
    Fat: 0.4g

# 잘못된 예: Fat이 Calories 안에 들어간 구조가 된다
Banana:
    Calories: 105
        Fat: 0.4g
```

- 데이터를 의도한 대로 표현했는지 들여쓰기를 반드시 검토한다.
- 들여쓰기에는 탭이 아니라 **공백**을 쓴다.

## 배열 안에 딕셔너리

배열의 각 항목을 딕셔너리로 만들 수 있다.

```yaml
Fruits:
    - Banana:
        Calories: 105
        Fat: 0.4g
    - Grape:
        Calories: 62
        Fat: 0.3g
```

## 딕셔너리 vs 배열

| 구분 | 순서 | 설명 |
|------|------|------|
| 딕셔너리 | 상관없음 | 속성의 순서가 바뀌어도 **같은 객체**로 본다. |
| 배열 | 중요 | 항목의 순서가 바뀌면 **다른 값**으로 본다. |

데이터 구조를 다룰 때 이 차이를 유의해야 한다.

## 주석

`#`으로 시작하는 줄은 **무시**된다.

```yaml
# 이 줄은 무시된다
Fruit: Apple
```
