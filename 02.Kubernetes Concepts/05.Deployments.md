# Deployments

## Deployment가 필요한 이유

프로덕션 환경에 웹 서버를 배포한다고 가정해 보자. 다음과 같은 요구가 생긴다.

| 요구 사항 | 설명 |
|-----------|------|
| **여러 인스턴스** | 웹 서버 인스턴스가 하나가 아니라 여러 개 필요하다. |
| **원활한 업그레이드** | Docker 레지스트리에 새 버전의 애플리케이션 빌드가 올라올 때마다 인스턴스를 업그레이드하고 싶다. |
| **롤백** | 업그레이드 후 예기치 않은 오류가 발생하면 최근 변경을 취소하고 이전 상태로 되돌리고 싶다. |
| **변경 사항 일괄 적용** | 웹 서버 버전 업그레이드, 스케일링, 리소스 할당 수정처럼 변경이 여러 개일 때, 명령마다 즉시 반영하지 않고 **일시 중지 → 모든 변경 → 재개**해서 한꺼번에 롤아웃하고 싶다. |

### 롤링 업데이트(Rolling Update)

모든 인스턴스를 **한꺼번에** 업그레이드하면 애플리케이션에 접속하는 사용자에게 영향을 줄 수 있다. 그래서 인스턴스를 **차례로 하나씩** 업그레이드하는데, 이 방식을 **롤링 업데이트**라고 한다.

이 모든 기능을 쿠버네티스의 **Deployment**가 제공한다.

## 오브젝트 계층 구조

```
Deployment
└── ReplicaSet
    └── Pod
        └── Container
```

- 지금까지는 애플리케이션의 단일 인스턴스를 담는 **Pod**를 다뤘다. 각 컨테이너는 Pod로 캡슐화된다.
- 여러 Pod는 [Replication Controller 또는 ReplicaSet](./04.Replication%20Controllers%20and%20ReplicaSets.md)으로 배포했다.
- **Deployment**는 계층에서 ReplicaSet보다 **더 상위**에 있는 오브젝트다.

Deployment로 할 수 있는 일은 다음과 같다.

- 롤링 업데이트로 인스턴스를 원활하게 업그레이드
- 변경 사항 실행 취소(롤백)
- 변경 사항 일시 중지 및 재개

## 정의 파일

Deployment 정의 파일은 ReplicaSet 정의 파일과 거의 같고, **`kind` 값만 다르다.**

`deployment-definition.yaml`

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp-deployment
  labels:
    app: myapp
    type: front-end
spec:
  template:
    metadata:
      name: myapp-pod
      labels:
        app: myapp
        type: front-end
    spec:
      containers:
        - name: nginx-container
          image: nginx
  replicas: 3
  selector:
    matchLabels:
      type: front-end
```

| 항목 | ReplicaSet | Deployment |
|------|-----------|------------|
| `apiVersion` | `apps/v1` | `apps/v1` |
| `kind` | `ReplicaSet` | `Deployment` |
| `spec` 구조 | `template`, `replicas`, `selector` | 동일 |

## 실습

| 명령어 | 확인할 수 있는 내용 |
|--------|---------------------|
| `kubectl create -f deployment.yaml` | Deployment가 하나 생성된다. |
| `kubectl get pods` | `replicas: 3` 설정대로 **Pod 3개가 생성**된다. |
| `kubectl describe deployment myapp-deployment` | Deployment의 상세 정보를 볼 수 있다. |

`describe` 출력에서 주로 보는 부분은 다음과 같다.

- **Pod Template**: Pod 템플릿에 정의한 컨테이너·이미지 등 Pod 정보
- **Events**: Deployment에서 발생한 이벤트 기록
