# LoadBalancer

## 왜 필요한가? (사용 사례)

4개의 노드로 구성된 클러스터에 **투표 앱(voting app)** 과 **결과 앱(result app)** 이 배포되어 있다고 하자.

- 외부 사용자가 접근할 수 있도록 두 앱에 **NodePort** 유형 Service를 만든다.
- NodePort Service는 **노드의 포트**에서 트래픽을 수신해 해당 앱의 Pod로 라우팅한다.
- 그렇다면 최종 사용자에게 **어떤 URL**을 알려 줘야 할까?

### NodePort의 URL

- **노드 IP + Service가 노출된 포트** 조합으로 접근한다.
  - 투표 앱: `노드IP:투표앱포트`
  - 결과 앱: `노드IP:결과앱포트`
- Pod가 **두 개의 노드에만** 배포되어 있어도, **클러스터의 모든 노드 IP**로 접근할 수 있다.
  - 예: 투표 앱 Pod가 IP `...70`, `...71` 노드에만 있어도 4개 노드 모두의 해당 포트로 접속된다.
  - Service가 클러스터의 모든 노드에 같은 `nodePort`를 열어 두기 때문이다. (→ [Services & NodePort](./01.Services%20%26%20NodePort.md))

| 앱 | 접근 가능한 URL (4개 노드 모두 가능) |
|----|--------------------------------------|
| 투표 앱 | `http://노드1:포트`, `http://노드2:포트`, `http://노드3:포트`, `http://노드4:포트` |
| 결과 앱 | 위와 동일한 형태, 다른 포트 |

### 하지만 이건 사용자가 원하는 형태가 아니다

- 사용자는 노드 IP:포트가 아니라 **하나의 URL**(예: `http://example-vote.com`)을 원한다.
- 노드 4개의 주소를 나눠 주는 것은 비현실적이다. 노드가 죽거나 추가되면 주소도 바뀐다.

## 해결 방법

### 1. 직접 로드 밸런서 구축

- **새 가상 머신**을 만들고 **HAProxy** 같은 로드 밸런서를 설치·구성해 노드들로 트래픽을 분산한다.
- 외부 부하 분산 기능을 직접 설정하고 **유지 관리**하는 일은 **지루하고 번거롭다.**

### 2. 클라우드 로드 밸런서 사용 (LoadBalancer 유형)

- **GCP, AWS, Azure** 같은 클라우드 플랫폼은 **네이티브 로드 밸런서**를 제공한다.
- 쿠버네티스는 이를 연동할 수 있어서, Service의 `type`을 `NodePort` 대신 **`LoadBalancer`** 로 **선언만 하면** 된다.
- 쿠버네티스가 클라우드 로드 밸런서를 자동으로 프로비저닝하고 노드들로 트래픽을 분산하며, 사용자에게는 **단일 외부 주소**가 생긴다.

```
사용자 ──▶ 클라우드 LB (단일 URL/IP) ──▶ 노드 IP:nodePort ──▶ Service ──▶ Pod
```

## 정의 파일

```yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp-service
spec:
  type: LoadBalancer
  ports:
    - targetPort: 80
      port: 80
      nodePort: 30008
  selector:
    app: myapp
    type: front-end
```

- NodePort와 비교하면 **`type`만 `LoadBalancer`로 바뀐다.**
- LoadBalancer를 쓰면 NodePort로 설정했을 때와 같이 **각 노드의 높은 번호 포트(30000번대)에 Service가 노출**되는 효과를 그대로 얻고, 그 위에 로드 밸런서가 추가된다.

## 주의

- 이 기능은 **지원되는 클라우드 플랫폼에서만** 동작한다.
- 지원되지 않는 환경(VirtualBox 로컬 클러스터 등)에서 `type: LoadBalancer`로 선언하면 **NodePort처럼만 동작**한다. 외부 IP는 할당되지 않고 `EXTERNAL-IP`가 `<pending>`으로 남는다.

> 로컬(minikube)에서는 `minikube tunnel`을 실행하면 LoadBalancer에 외부 IP를 부여해 볼 수 있다.

## 정리

| 유형 | 용도 |
|------|------|
| **NodePort** | 노드 IP:포트로 외부 노출. 노드마다 주소가 다름 |
| **ClusterIP** | 클러스터 내부 통신용 가상 IP |
| **LoadBalancer** | 클라우드 LB로 **단일 URL**을 제공. 지원 플랫폼에서만 동작 |
