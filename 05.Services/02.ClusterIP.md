# ClusterIP

## 왜 필요한가? (사용 사례)

풀스택 웹 애플리케이션에는 보통 애플리케이션의 각 부분을 호스팅하는 **여러 종류의 Pod**가 있다.

| 계층 | 예시 |
|------|------|
| 프론트엔드 | 웹 서버를 실행하는 여러 Pod |
| 백엔드 | 백엔드 서버를 실행하는 또 다른 Pod 세트 |
| 키-값 저장소 | Redis를 실행하는 Pod 세트 |
| 영구 데이터베이스 | MySQL 등을 실행하는 Pod |

- 프론트엔드는 백엔드와 통신하고, 백엔드는 Redis나 DB와 통신해야 한다.
- 그렇다면 계층 사이의 연결은 **어떻게** 설정하는 것이 올바를까?

### Pod IP로는 안 된다

- 모든 Pod에는 IP 주소가 할당되지만, 이 IP는 **고정되어 있지 않다.**
- Pod는 언제든 다운될 수 있고, 새로운 Pod가 계속 만들어질 수 있다. (재생성되면 IP도 바뀐다.)
- 따라서 **내부 통신에 Pod IP를 사용할 수 없다.**
- 프론트엔드의 첫 번째 Pod가 백엔드의 어느 Pod에 연결할지 누가 결정할까?

## Service로 해결

- 쿠버네티스 **Service**는 Pod를 함께 **그룹화**하고, 그 그룹에 접근할 수 있는 **단일 인터페이스**를 제공한다.
- 백엔드 Pod용으로 만든 Service는 모든 백엔드 Pod를 하나로 묶고, 다른 Pod가 이 Service를 통해 접근하게 해 준다.
- 요청은 Service 아래의 Pod 중 **하나로 무작위 전달**된다.
- Redis용 Service를 추가로 만들면, 백엔드 Pod가 Service를 통해 Redis에 접근할 수 있다.

```
프론트엔드 Pod들 ──▶ back-end Service ──▶ 백엔드 Pod들 ──▶ redis Service ──▶ Redis Pod들
```

- 이렇게 하면 **마이크로서비스(MSA) 기반 애플리케이션**을 클러스터에 쉽고 효과적으로 배포할 수 있다.
- 각 계층은 다른 서비스 간 통신에 영향을 주지 않고 **필요에 따라 확장하거나 이동**할 수 있다.

## ClusterIP란?

- 각 Service는 클러스터 안에서 **IP와 이름**을 할당받는다.
- 다른 Pod는 이 **이름(또는 IP)** 으로 Service에 접근한다.
- 이러한 유형의 Service를 **ClusterIP**라고 한다. (클러스터 **내부 전용**)

> ClusterIP는 Service의 **기본 유형**이다. `type`을 지정하지 않아도 된다.

## 정의 파일

Service도 다른 오브젝트처럼 **정의 파일**로 만든다.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: back-end
spec:
  type: ClusterIP
  ports:
    - targetPort: 80
      port: 80
  selector:
    app: myapp
    type: back-end
```

### 포트

| 포트 | 위치 | 설명 |
|------|------|------|
| `targetPort` | **Pod(백엔드)** | 백엔드가 노출되는 포트. Service가 요청을 전달하는 대상 |
| `port` | **Service** | Service가 노출되는 포트 |

### Pod와 연결: label & selector

- Service를 특정 Pod 세트에 연결하려면 **selector**를 사용한다.
- **Pod 정의 파일의 `labels`를 복사**해서 Service의 `spec.selector` 아래에 붙여 넣으면 끝이다.

```yaml
# pod-definition.yml (백엔드 Pod)
metadata:
  labels:
    app: myapp
    type: back-end
```

## 생성 및 확인

```bash
kubectl create -f service-definition.yml
kubectl get services
```

## 정리

- Pod IP는 바뀌므로 **내부 통신은 Service(ClusterIP)** 로 한다.
- ClusterIP Service는 Pod 그룹에 **단일 접점(IP + 이름)** 을 제공하고 요청을 **무작위 분산**한다.
- `type` 생략 시 기본값이 ClusterIP이며, `targetPort`·`port`·`selector`만 맞추면 된다.
- 외부 노출이 필요하면 [NodePort](./01.Services%20%26%20NodePort.md)를 쓴다.
